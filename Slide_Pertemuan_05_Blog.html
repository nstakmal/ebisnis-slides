Komponen Fundamental

4 Pilar Utama Penyusun Infrastruktur E-Bisnis

Pertemuan 05 • Slide 3/12
🖥️ 1. Hardware

Perangkat Fisik Komputasi

  • Server Fisik (Rak Data Center).
  • Load Balancer Hardware.
  • Storage SAN/NAS untuk penyimpanan data terdistribusi.
  • Perangkat Klien (PC, Smartphone, Tablet kasir POS).
💾 2. Software

Aplikasi & Sistem Operasi

  • Sistem Operasi Server (Linux Ubuntu/Debian/RHEL).
  • Web Server (Nginx, Apache, Caddy).
  • Database Management System (MySQL, PostgreSQL, MongoDB).
  • E-Commerce Software Engine.
📡 3. Network

Jalur Telekomunikasi

  • Bandwidth Internet & CDN (Cloudflare).
  • Domain Name System (DNS).
  • Protokol Keamanan (HTTPS / TLS 1.3).
  • VPN & Firewall Jaringan (WAF).
☁️ 4. Cloud & Data

Penyimpanan & Layanan

  • Layanan Cloud (AWS, Google Cloud, Alibaba Cloud).
  • Data Warehouse & Data Lake.
  • Object Storage untuk ribuan foto produk (Amazon S3 / Google GCS).
Definisi Standar: "Infrastruktur e-bisnis adalah arsitektur hardware, software, konten, dan data yang digunakan untuk memberikan layanan bisnis digital kepada karyawan, pelanggan, dan mitra bisnis secara andal." (Modul E-Bisnis KB 4).
Arsitektur Perangkat Lunak

Arsitektur Standar Web E-Bisnis: 3-Tier Layer

Pertemuan 05 • Slide 4/12
Mengapa Harus Dipisah 3 Lapisan?
  • 1. Keamanan Data (Security Isolation):
    Pengguna di Tier 1 tidak pernah bisa langsung mengakses database (Tier 3). Semua permintaan disaring dan divalidasi ketat oleh logika Tier 2.
  • 2. Kemudahan Maintenance & Update:
    Jika tim desainer ingin mengubah tampilan warna tombol web (Tier 1), mereka tidak perlu mengutak-atik kode database atau server backend.
  • 3. Skalabilitas Independen:
    Jika pengunjung membludak, kita cukup menambah server aplikasi (Tier 2) tanpa harus mengubah struktur database.
Paradigma Modern

Cloud Computing: IaaS vs PaaS vs SaaS

Pertemuan 05 • Slide 5/12

Memahami 3 model layanan cloud dengan Analogi "Pizza as a Service":

1. On-Premise (Tradisional)
"Bikin Pizza di Rumah"

Anda urus SEMUANYA sendiri:

Beli oven, beli gas, racik adonan, sediakan meja makan, cuci piring sendiri.
Di TI: Beli server fisik, pasang AC data center, urus kabel LAN sendiri.
2. IaaS (Infrastructure)
"Beli Adonan Beku"

Sewa mesin mentah:

Adonan & oven disewa, Anda tinggal masak dan sajikan.
Di TI: Sewa Virtual Machine di AWS EC2 / Google Compute Engine. Anda pasang OS dan koding sendiri.
3. PaaS (Platform)
"Pesan Pizza Delivery"

Fokus bikin kode saja:

Pizza diantar matang, Anda cuma siapkan meja & minuman.
Di TI: Heroku, Vercel, Firebase. Anda cuma upload kode aplikasi, server otomatis jalan.
4. SaaS (Software)
"Makan di Resto Pizza Hut"

Tinggal pakai langsung:

Duduk manis, makan, bayar, selesai.
Di TI: Shopify, Google Workspace, Canva, SAP Cloud. Langsung pakai lewat browser.
Rekomendasi Proyek Mahasiswa: Untuk tugas kelompok e-bisnis nanti, gunakan model PaaS (Vercel/Railway) atau SaaS (Shopify/WooCommerce) agar tidak pusing mengonfigurasi hardware server dari nol.
Integrasi Korporat

Enterprise Application Integration (EAI)

Pertemuan 05 • Slide 6/12
🍝 Masalah Spaghetti Architecture

Ketika perusahaan punya 5 sistem berbeda (Toko Web, ERP Gudang, CRM Sales, Akuntansi, dan HRD) dan semuanya dihubungkan secara manual satu per satu:

  • Koneksi antar sistem rumit semrawut seperti kabel kusut.
  • Jika 1 aplikasi di-update, 4 aplikasi lainnya bisa ikut rusak/crash!
  • Sangat sulit menambah fitur atau mitra baru.
🎯 Solusi: Pendekatan EAI Hub & Bus

EAI bertindak sebagai penerjemah dan jembatan sentral (*Middleware*):

  • Setiap aplikasi hanya perlu terhubung ke 1 titik: Enterprise Service Bus (ESB).
  • Format data lama (XML/EDI) otomatis dikonversi menjadi format web modern (JSON).
  • Integrasi antar divisi korporat berjalan mulus tanpa merusak sistem lawas (*Legacy Systems*).
Standar Industri Saat Ini

Jantung E-Bisnis Modern: API Economy & Webhooks

Pertemuan 05 • Slide 7/12
1. REST API (Request - Response)

Aplikasi Anda bertanya, server luar menjawab.

GET /api/ongkir?asal=kisaran&tujuan=medan

// Response JSON:
{
  "kurir": "JNE REG",
  "tarif": 15000,
  "estimasi_hari": "1-2"
}

Digunakan saat website butuh data realtime (cek ongkos kirim, cek stok supplier).

2. Webhooks (Event-Driven Alert)

Server luar yang proaktif menepuk bahu website Anda saat ada kejadian!

POST https://tokoku.com/webhook/payment

// Sinyal Masuk dari Midtrans:
{
  "order_id": "ORD-9912",
  "status": "PAID",
  "channel": "QRIS_BCA"
}

Digunakan saat pembeli sudah bayar di m-banking. Website tidak perlu refresh berulang kali, otomatis status order berubah lunas!

Konsep API Economy: Saat ini bisnis tidak perlu membuat segalanya sendiri. Mau fitur peta? Pakai Google Maps API. Mau kasir? Pakai Midtrans API. Mau kirim WA? Pakai Twilio / Fonnte API. Bisnis e-commerce modern dibangun dari rangkain API (*Lego-like Architecture*).
Kinerja & Keandalan

Mengapa Server Tokopedia Tidak Jebol Saat Flash Sale 12.12?

Pertemuan 05 • Slide 8/12
⚖️ 1. Load Balancer

Berperan seperti polisi lalu lintas. Membagi 1 juta pengunjung yang datang bersamaan ke 50 server berbeda secara adil sehingga tidak ada 1 server pun yang kepanasan atau hang.

⚡ 2. Redis Caching

Menyimpan data katalog produk di memori RAM super cepat. Ketika 100.000 orang melihat foto sepatu yang sama, server tidak membebani database utama berulang kali.

📈 3. Auto-Scaling

Kapasitas server cloud bertambah otomatis secara elastis! Jika traffic biasa butuh 2 server, saat jam promo 12.12 server otomatis menggandakan diri menjadi 20 server, lalu mengecil lagi setelah promo selesai.

Keamanan Siber & Kepatuhan

Lapisan Pertahanan Keamanan Siber E-Bisnis

Pertemuan 05 • Slide 9/12
🛡️ 3 Lapisan Pertahanan Wajib
  • 1. Data in Transit (Enkripsi Jalur):
    Protokol HTTPS (SSL/TLS 1.3). Menjamin nomor kartu kredit dan kata sandi diacak sehingga tidak bisa disadap di jaringan Wi-Fi umum (*Anti-Sniffing*).
  • 2. Data at Rest (Enkripsi Penyimpanan):
    Data password di database wajib di-hash satu arah (Bcrypt/Argon2). Nomor rekening dan data pribadi dienkripsi AES-256 agar jika server diretas, hacker hanya mendapat teks acak tak terbaca.
  • 3. Perimeter Defense (Web Application Firewall):
    Cloudflare / AWS WAF untuk menyaring serangan DDoS dan serangan injeksi SQL jahat sebelum sampai ke server.
⚖️ Kepatuhan Regulasi Indonesia

Sesuai amanat UU No. 27 Tahun 2022 tentang Perlindungan Data Pribadi (UU PDP):

⚠️ Setiap pengembang dan pemilik sistem e-bisnis diwajibkan secara hukum menerapkan standar keamanan teknis yang memadai.

Jika terjadi kebocoran data pengguna akibat kelalaian sistem (tanpa enkripsi), perusahaan terancam sanksi penghentian operasional dan denda ganti rugi hingga miliaran rupiah.
Pesan Moral untuk Mahasiswa SI: Jangan pernah menyimpan password pengguna dalam bentuk plain text di database! Gunakan fungsi hash dan protokol keamanan standar industri.
Siklus Hidup Pengembangan

5 Tahap Pembangunan Infrastruktur Sistem E-Bisnis

Pertemuan 05 • Slide 10/12

Berdasarkan Modul E-Bisnis KB 4 (Siklus Rekayasa Sistem Informasi Bisnis):

TAHAP 1
Perencanaan

Menentukan model bisnis, studi kelayakan anggaran, dan pemilihan target audiens.

TAHAP 2
Analisis

Analisis kebutuhan fungsional (fitur checkout, metode bayar) dan non-fungsional (kecepatan, keamanan).

TAHAP 3
Perancangan

Desain UI/UX Wireframe, pemodelan database ERD, dan spesifikasi arsitektur 3-tier.

TAHAP 4
Penerapan

Coding frontend/backend, setup cloud hosting, integrasi API gateway, dan pengujian sistem (*Testing*).

TAHAP 5
Evaluasi

Pemantauan performa server harian, ulasan pelanggan, dan perbaikan bug secara berkala.

Penting untuk Proyek PBL Mahasiswa: Seluruh tugas proyek kelompok yang akan dikerjakan di semester ini akan mengikuti tahapan 1 sampai 5 ini secara terstruktur!
Praktik Proyek PBL

Panduan Memilih Teknologi untuk Tugas Kelompok Anda

Pertemuan 05 • Slide 11/12

Setiap kelompok mahasiswa dapat memilih salah satu dari 2 jalur teknologi pengembangan berikut:

🚀 Jalur A: Low-Code CMS (Cepat & Siap Bisnis)
Pilihan: WordPress + WooCommerce / Shopify
  • Kelebihan: Antarmuka admin toko sudah siap pakai, fitur keranjang belanja dan invoice otomatis tersedia.
  • Integrasi: Sangat mudah dipasangi plugin Payment Gateway Midtrans dan plugin ongkir RajaOngkir.
  • Cocok untuk: Kelompok yang ingin fokus pada strategi marketing, katalog produk, dan model bisnis.
💻 Jalur B: Custom Web Framework (Eksplorasi SI)
Pilihan: PHP Laravel / Next.js / Node.js Express
  • Kelebihan: Fleksibilitas tinggi dalam merancang skema database sendiri dan integrasi REST API kustom.
  • Tantangan: Butuh waktu koding lebih banyak untuk membangun halaman cart dan otentikasi login.
  • Cocok untuk: Kelompok yang ingin melatih kemampuan koding backend dan arsitektur database.
Toleransi Dosen: Keduanya bernilai sama tinggi! Yang dinilai bukan seberapa rumit kodingnya, melainkan bagaimana sistem tersebut menyelesaikan masalah bisnis dan berfungsi dengan aman.

Rangkuman Kunci & Kuis Cepat Pemahaman

Pertemuan 05 • Slide 12/12
Takeaway Pembelajaran Pertemuan 05
  • Infrastruktur e-bisnis ditopang oleh Hardware, Software, Network, dan Cloud.
  • Arsitektur 3-Tier memisahkan Presentation, Business Logic, dan Database demi keamanan dan skalabilitas.
  • Ekosistem Cloud (IaaS/PaaS/SaaS) membebaskan bisnis dari kewajiban membeli server fisik yang mahal.
  • REST API dan Webhooks adalah bahasa pengikat antar sistem yang memungkinkan toko online terhubung ke bank dan logistik dalam hitungan detik.
